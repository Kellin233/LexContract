# 📜 LexTrace

**面向合同与法律文档的可验证审查 Agent 系统**

从分散的合同条款中找到相关原文，组织证据并生成可复核的审查结论。

## 项目简介

LexTrace 用于合同审查、法律研究和企业合规辅助。用户提出一个自然语言问题后，系统会在指定的合同文档范围内定位相关条款，恢复完整上下文，核验引用来源，再生成带证据的结构化审查报告。

项目的核心目标不是只生成一个答案，而是让每个重要判断都能回答三个问题：依据了哪段原文、原文位于哪里、引用是否经过校验。这样，审查结果既适合阅读，也便于复核、归档和后续系统接入。

## 解决的问题

- 相关条款分散在不同章节或多份文档中，单次检索难以覆盖完整事实。
- 只依赖模型总结容易出现引用偏移、脱离原文或遗漏冲突条款。
- 搜索片段缺少章节和页码上下文，难以形成可验证的证据链。
- 人工审查过程重复度高，难以用统一标准评估结果质量。

## 核心设计

**Agent 编排。** 系统将研究过程拆成职责清晰的任务链，而不是让一个 Agent 同时负责拆题、检索和下结论。规划 Agent（Planner）先把复杂问题拆成相互独立的调查要点；搜索 Agent（Searcher）围绕各要点并行取证；复核 Agent（Reviewer）检查证据覆盖度、冲突和缺口，并在需要时触发增量规划与补查；报告 Agent（Refiner）只基于已经确认的证据生成最终结论。整体采用有向任务图组织，并对并发数、检索轮次和全局超时进行约束。

系统同时支持两种研究链路：快速链路为“规划 → 并行搜索 → 报告”，适合低延迟查询；复核增量链路为“规划 → 并行搜索 → 复核 → 补查 → 报告”，适合需要覆盖多个事实角度的复杂审查。

**搜索服务。** 文档进入系统时会保留全文、章节层级、页码和字符位置。查询阶段采用语义向量检索与 BM25 关键词检索的混合召回，并融合候选排序结果；搜索 Agent 先用候选片段完成粗定位，再通过关键词精确匹配、章节定位和切片展开恢复完整条款。搜索工具支持多轮调用，能够在一次研究中从不同表述、章节和文档范围补充证据，同时强制限定在当前会话或指定文档内。

**证据处理与追溯。** 检索命中只是候选，不会直接作为最终引用。系统会从存储的合同原文中物化连续条款，并为证据记录文档、章节、页码、字符范围和来源切片。进入报告前，程序逐字符核对“引用内容”是否等于“原文对应区间”，同时检查来源切片与文档位置是否一致；校验失败的证据不会进入结论。证据按文档和字符区间去重，每条证据分配稳定的运行期编号，报告中的引用编号可以还原到完整原文和具体位置。

**上下文与协作。** 共享证据索引作为 Agent 之间的协作记忆：搜索阶段主要传递证据编号和元数据，需要分析时再按编号读取原文。重复条款和重复章节不会反复注入模型上下文，但完整原文始终保留在证据层。系统同时记录各环节的调用次数和 token 估算，用于控制上下文预算、比较编排策略和定位检索瓶颈。

## 工作流程

```text
用户问题
   ↓
拆分调查要点
   ↓
多路混合检索与多轮取证
   ↓
恢复完整条款并校验证据
   ↓
检查覆盖度、冲突和缺口
   ↓
生成带引用的审查报告
```

证据不足时，报告会明确列出尚未确认的事实和缺口，不把“没有找到依据”误写成“合同没有相关约定”。

## 项目特点

- **原文优先：** 关键结论建立在合同原文之上，引用内容不由模型改写。
- **职责分离：** 规划、取证、复核和结论生成各自独立，降低错误在链路中扩散的风险。
- **混合搜索：** 同时利用语义相似度和关键词匹配，兼顾概念理解与条款编号、专有表述等精确查找。
- **证据可回溯：** 引用关联文档、章节、页码和字符区间，支持从报告回到完整条款。
- **范围可控：** 检索可以限定在指定文档集合，适合单合同审查和多合同对比。
- **过程可评估：** 记录证据校验、引用有效性、检索覆盖和资源消耗，便于持续比较系统效果。
- **模型解耦：** 通过统一的模型调用接口连接本地或远程的 OpenAI 兼容服务，并可为不同 Agent 分配不同模型。

## 评测结果

评测同时覆盖端到端分类和证据检索。ContractNLI 检查系统能否基于合同证据判断“支持、矛盾或无法确定”；LegalBenchRAG 检查搜索 Agent 找到的文档及字符区间与标注答案的重叠程度。指标由规则计算，不依赖主观描述；运行过程还会记录引用校验和检索遥测。

**ContractNLI：完整链路，150 条样本（2026-08，默认复核增量编排）**

| 指标 | 结果 |
| --- | ---: |
| Accuracy | **80.00%** |
| Weighted F1 | **79.78%** |
| Contradiction F1 | 72.73% |
| Entailment F1 | 84.35% |
| Neutral F1 | 76.67% |
| 引用有效性 | **100%（233 / 233）** |
| 评测错误 | 0 / 150 |

**LegalBenchRAG：Searcher 链路，100 条查询（2026-08）**

| 指标 | 整体结果 |
| --- | ---: |
| 文档级 Precision / Recall | **86.39% / 86.39%** |
| 字符级 Span Recall | **75.99%** |
| 字符级 Span Precision | 7.88% |
| 字符级 Span F1 | 12.90% |
| 证据原文校验通过率 | **100%（200 / 200）** |

文档级指标反映“找对并覆盖相关文档”的能力；Span 指标按字符区间计算。系统倾向于恢复完整条款，因此通常会带来更高的覆盖率和相对较低的字符精度，这正是“证据保留完整原文”设计的结果。

## 技术栈

Python、asyncio、PostgreSQL、pgvector、BM25、bge-m3，以及支持工具调用的 OpenAI 兼容模型服务。

## 适用场景

- 合同条款查询与要点提取
- 付款、交付、违约责任和终止条件审查
- 多份合同之间的义务、限制和风险对比
- 合规检查与法律研究辅助
- 带原文引用的合同问答和审查报告
